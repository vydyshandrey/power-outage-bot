# Інструкція для ШІ-асистента: розгортання бота

Цей файл для ШІ-асистентів: Claude, ChatGPT/Codex, Cursor тощо. Людина попросила тебе розгорнути цей проєкт для її дому. Ти ведеш процес, а людина робить лише те, що може зробити тільки вона сама. Говори з нею простою мовою: вона може бути не айтішником.

Та сама інструкція для людини — [docs/install-guide.md](docs/install-guide.md). Іди за нею крок за кроком.

## Що це

Telegram-бот на Cloudflare Workers (безкоштовний тариф).

- Читає стан мережі з хмари інвертора: DeyeCloud, SmartESS / WatchPower / SmartClient (DESS Monitor, ShineMonitor) або SmartValue (ValueClouds).
- Коли світло зникає, вимикає пристрої об'єкта (зараз — бойлери Midea). Коли світло стабільно є 5 хв, вмикає їх назад, але лише ті, що вимикала автоматика.
- Кілька об'єктів, адмін і користувачі з рівнями доступу (немає · бачить · керує), історія, редаговані тексти повідомлень.

**Де що живе:**

| Що                                                              | Де                                                 |
| --------------------------------------------------------------- | -------------------------------------------------- |
| Об'єкти, інвертори, пристрої, назви, тексти, люди, часовий пояс | база D1; людина налаштовує в боті: ⚙️ Налаштування |
| Паролі й токени                                                 | секрети Cloudflare                                 |
| Технічні налаштування воркера (назва, база, розклад)            | `wrangler.toml`                                    |
| Код                                                             | `src/`, вхідна точка `src/index.js`                |

## Непорушні правила

1. **Паролі, токени й ключі людина вводить сама, прямо в Cloudflare** (воркер → Settings → Variables and Secrets) або у твій термінал через `wrangler secret put`. Ніколи не проси вставити їх у чат. Якщо людина все ж вставила, порадь змінити цей пароль чи токен.
2. **Реєстрацію в сервісах і підтвердження доступів робить людина.** Акаунти, вхід, кнопки «Authorize» та «Install» — за нею. Ти пояснюєш, куди натиснути, і чекаєш.
3. **Нічого не публікуй від імені людини** й не роби її репозиторій публічним без прямого прохання.
4. **Не змінюй код у `src/`, щоб «спростити» розгортання.** Налаштування — у боті, паролі — у секретах. Зміни в коді зламають оновлення кнопкою.

## Кроки

1. **Telegram:** людина створює бота в @BotFather і зберігає токен. Ключ адміна (`ACCESS_KEY`, 30+ латинських літер і цифр) можна згенерувати й показати людині: це не пароль від стороннього сервісу.
2. **Розгортання:** кнопка «Deploy to Cloudflare» в README. Cloudflare копіює проєкт у GitHub людини, створює базу D1 і питає секрети `TG_BOT_TOKEN` і `ACCESS_KEY`.
   - Шлях через термінал (Claude Code, Codex): `npx wrangler login` (людина підтверджує в браузері) → `npx wrangler deploy` (база створиться автоматично) → `npx wrangler secret put TG_BOT_TOKEN` і `ACCESS_KEY` — значення людина вводить сама.
3. **Підключення:** людина відкриває `<адреса воркера>/setup?key=<ACCESS_KEY>` (у відповіді `"webhook":{"ok":true…}`), потім пише боту `/start <ACCESS_KEY>` і отримує «✅ Ти адмін».
4. **Налаштування в боті:** ⚙️ Налаштування → 🏠 Об'єкти → ➕ Додати об'єкт (назва), далі бот пропонує додати його інвертор. Інвертор — пристрій об'єкта, як і бойлер. Бот сам каже, які секрети потрібні для обраної хмари, і після їх додавання показує інвертори для вибору. Деталі по кожній хмарі — у [install-guide](docs/install-guide.md), крок 4.
5. **Пристрої:** ⚙️ Налаштування → 🔌 Пристрої → ➕ Додати пристрій. Для Midea потрібен окремий акаунт SmartHome, з яким основний поділився бойлером.
6. **Перевірка:** «📊 Статус» показує світло, батарею, пристрої; «Дані …: N хв тому» — до ~10 хв.

## Типові проблеми

| Симптом                             | Що робити                                                                                 |
| ----------------------------------- | ----------------------------------------------------------------------------------------- |
| `/setup` повертає `forbidden`       | неправильний `key`; перевір `ACCESS_KEY` у секретах                                       |
| Бот мовчить на `/start`             | не відкривали `/setup`, або неправильний `TG_BOT_TOKEN`                                   |
| «Не вдалося увійти в хмару»         | неправильні логін чи пароль у секретах; для Deye ще AppId/AppSecret і регіон (`DEYE_API`) |
| SmartESS: `ERR_PASSWORD_VERIF_FAIL` | неправильний пароль, або акаунт SmartClient — обери в боті «SmartClient for Solar»        |
| Що бачать хмари                     | `<адреса воркера>/discover?key=<ACCESS_KEY>` — діагностика по кожному об'єкту             |
| `Midea 3102` час від часу           | відома нестабільність хмари Midea; бот сам повторює спроби                                |

## Оновлення

Нова версія приходить адміну повідомленням з кнопкою «⬆️ Оновити». Вона запускає GitHub Actions «Оновлення» (`.github/workflows/update.yml`) у копії людини: нова версія замінює код, проходять тести, Cloudflare розгортає. Дані й налаштування в базі не змінюються. Для кнопки людина вказує свою копію в ⚙️ Налаштування → 🔗 Репозиторій; секрет `GH_TOKEN` (fine-grained, Actions: Read and write лише на цю копію) дозволяє боту запускати оновлення самому.

## Для змін у коді

- `npm install`, потім `npm run check`: лінтер, форматування й тести на імітації хмар і Telegram. Запускай перед кожною зміною.
- Нова версія: збільш `VERSION` у `src/config.js` і `version` у `package.json`, додай запис у `CHANGELOG.md`. Зміни структури бази — лише через міграцію в `src/db.js`, щоб наявні встановлення оновились без втрат.
